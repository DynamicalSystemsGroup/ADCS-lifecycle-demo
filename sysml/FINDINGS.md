# Demo model: gaps and workarounds

Gaps the GeoSatADCS model (`satellite.sysml`, `model.py`) works around, with OpenSysML 0.10.0.
Started from the probe's gap list (`sysml/probe/FINDINGS.md`); items marked "new" were found while building the model.

| # | gap | workaround in the demo |
|---|---|---|
| 1 | The standard library has no home for an evidence hash beyond `AnalysisTooling::ToolExecution::uri`, and no timestamp, version or digest field. | The hash goes in `uri = "sha256:<hash>"`. No time is recorded in the model; the Git commit and the Flexo commit timestamp carry the time. No attribute is invented. |
| 2 | The Flexo SysML v2 service does not persist commit descriptions. | Each Flexo commit is tagged `git-<sha>`; nothing in the model carries the SHA. |
| 3 | `::>` (reference-subsetting) and def-typed named `satisfy` load but are not evaluated: `verify_satisfaction` returns `no requirement to satisfy`. | The attestation uses the usage-subsetting form `satisfy requirement att :> req001 by <design>;` (chosen because OpenSysML 0.10.0 evaluates it and it traces to the req001 usage). |
| 4 | A `verify` objective contributes no verdict: a case with no `return` binding is `inconclusive` whether the constraint holds or not. | The case binds `PassIf(req001(adcs))`, so the verdict is computed from the requirement itself. (A second case with no binding, for REQ-004, was removed from the demo: REQ-004 out of scope.) |
| 5 | `verify_satisfaction()` with no argument returns one error per `verify` objective in a verification def (`no value for feature adcs`). | `evaluate` scopes each call to one `att_*` claim by name. |
| 6 | (new) `evaluate` reads verification names, claim names and part names from the model text with regular expressions, not from `to_api_json()`. | Kept small on purpose. A block that does not follow the `vc<N>_<design>`, `att_<design>`, `part <name> : ADCS` shapes is not reported. |
| 7 | (new) `VerificationMethod` takes `VerificationMethodKind::analyze` (the library literals are `inspect`, `analyze`, `demo`, `test`). It parses on both verification defs and does not change the verdicts. Nothing evaluates it. | Used as documentation only. |
| 8 | (new) REQ-001's text mentions pointing accuracy (0.1 degrees, 3-sigma) as well as 120 s, but the simulation yields a settling time only. | The `doc` is verbatim from `structural/satellite.ttl`. The `require constraint` encodes only the 120 s clause. A pass means "settling time within 120 s in this model", not the full text; the human judges the rest. |
| 9 | (new) Removed from demo (REQ-004 out of scope, DL-25). It recorded that the tuned design's peak torque equals the limit because `analysis/numerical.py` clips torque with `np.clip`. The model no longer carries `peakTorque` or `torqueLimit`; the approved adequacy text says the simulation enforces the actuator torque limit. | None needed. |
| 10 | (new) `Quantity.magnitude` is a `Fraction`. | `evaluate` returns floats and plain bools only. |
| 11 | (new) The two exports disagree on the anonymous requirement inside `verify` (`SatisfyRequirementUsage` in `query()`, `RequirementUsage` in `to_api_json()`). | Not used by the model. |
| 12 | (new) The standard library has no construct for "re-attestation required". | It is expressed as a `StatusInfo` with status `tbc` and no originator (`status_block("req001")`), plus the text diff of the model that shows the earlier `not satisfy` removed. No person is named and no Rationale is written, because no person has acted. |
| 13 | (new) `to_api_json` exports the standard-library definitions the model references. | A Flexo element diff of one user-model change also lists the library definitions it references. The notebook tells them apart by whether an element's owner chain reaches the model package, and reports them as their own group. |
| 14 | (new) The standard library has no "supersedes" construct. | The attestation commit also removes the pending-status marker written when the evidence changed, because the standard library has no "supersedes" construct; the removal is shown as its own diff group. The marker is recognised from its content (a `StatusInfo` about `req001`, status `tbc`, no originator), not by name, and the library definition only it referenced (the `tbc` literal) leaves the export with it. The pending-marker removal is reported together with any standard-library definition that only the marker referenced. |
| 15 | (new) Adequacy is a human judgement, but the standard library's `Rationale` has no author field. | Resolved: adequacy is recorded as a Rationale plus a StatusInfo naming the person (originator), both about the design. `Rationale` itself still has no author field; the person is carried by the StatusInfo beside it. `status = done` on this StatusInfo means the adequacy judgement is recorded; it does not mean the design is accepted or the requirement satisfied. |
| 16 | (new) `analysis/symbolic.py` `wheel_momentum_bound_symbolic` / `evaluate_wheel_momentum` compute `h_peak = Kd * theta_0 * sqrt(Kp / (2 J))`. Kd is N·m·s/rad, theta_0 is rad and the root is 1/s, so the result has units of N·m (a torque), not N·m·s (a momentum), yet it is named and compared as a wheel-momentum bound. | Flagged, not fixed, and not used in the demo: the model carries no momentum attribute and `satellite.sysml` never reads this value. |
| 17 | (new) A second evidence source: the linear (SymPy) settling estimate, beside the scipy simulation. The standard library has no "estimate" or "method" field. | `ADCS` gains `settlingTimeEstimate : ISQ::DurationValue`; the requirement's constraint stays on `settlingTime`, so the estimate supports the human's judgement and never decides a verdict. Each source is its own `AnalysisTooling::ToolExecution` (toolName and `sha256:` uri) with the feature-chain target `about <design>::settlingTime` and `about <design>::settlingTimeEstimate`. Probed with OpenSysML 0.10.0: the chain loads with 0 diagnostics and annotates the design's own value-bearing redefinition (the export names these redefinitions anonymously, `<design>::@N`). Verdicts are unchanged. |
| 18 | (new) The adequacy judgement belongs to the scoping assumptions of the analysis, not to a design. The standard library's `analysis def` is the natural home. | `satellite.sysml` declares `analysis def SettlingAnalysis { doc /* scoping assumptions */ subject adcs : ADCS; }`. Probed on OpenSysML 0.10.0: it loads strict with 0 diagnostics, exports as `AnalysisCaseDefinition`, and `ModelingMetadata::Rationale` / `StatusInfo` can be attached with `about SettlingAnalysis`. `model.adequacy_block` emits them once; `evidence_block` no longer writes any adequacy. |
| 19 | (new) Per-axis settling and torque-limit saturation have no home in `ISQ::DurationValue` attributes without changing `ADCS`. | `evidence_block(per_axis=...)` writes them as `//` comment lines; `settlingTime` carries the worst axis. Comments are not elements, so they are not queryable. |
| 20 | (new) A formal check of the linear model (`sysml/linear_region.sysml`, `sysml/formal.py`). REDK `verify_constraint(engine="solve")` with Z3 needs `OPENSYSML_SMT` pointing at a z3 binary; the `z3-solver` wheel ships one next to the interpreter. The tool's own output says "proved by solve"; the demo's label is "Z3 finds no counterexample in this box for the linear model", a model-level result. The constraint source is a template: inertias, box and saturation limit are filled from the repo's code. | If z3 is missing the captured output (`talk/assets/formal-fallback.txt`, from a real run) is returned with `engine="captured"`. |
| 21 | (new) An action simulation in the model (`sysml/slew_sim.sysml`, run by `execute_action`). Euler steps of dt on one axis reproduce (4,25) as 119.5 s at dt=0.5 and 120.5 s at dt=0.05: the in-model simulation's step size changes the verdict. The investigation's scratch version labelled J=327.1 as the y axis; it is the x axis inertia (`evaluate_inertia`), and x is the worst axis at (4,25). | `evidence.inmodel_settling(kp, kd, dt, axis="x")`. |
