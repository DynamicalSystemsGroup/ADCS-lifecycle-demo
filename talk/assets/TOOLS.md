# Tool-output assets

Every `tool-*` file here is output of the tool named below, produced on 2026-10-14 by
`uv run python scripts/build_tool_assets.py` (after `bash scripts/fetch_tools.sh`). Rebuilding
gives byte-identical files. Nothing is hand-edited; the PNG is cropped.

Tools: `sysml` (OpenSysML CLI) v0.10.0, `sysmlv2` (sysml-toolkit) 0.10.2, PlantUML 1.2026.8,
z3 5.3.0.0 (the `z3-solver` wheel, via `uv run --with`, not a project dependency), Google Chrome
(headless) for the screenshot. Models are built by `sysml/model.py` (`sysml.views.design_model`).

## What the assets do and do not show

- The requirement views colour REQ-001 by the verdict of the verification case that verifies it.
  This is verification (automated). The attestation is not drawn: in this REDK build the
  requirement rendering draws neither the design part nor the `satisfy requirement att_x :> req001 by x;`
  claim (the claim is the usage-subsetting form `sysml/model.py` writes; the rendering drew a
  `satisfy` edge only for the plain `satisfy r by x;` form in a probe). The structure view shows the part def.
- `tool-verify.txt`: `RegionPasses` is the box Kp in [4, 6], Kd in [22, 25]: z3 reports it holds for
  all values in the box, for the linear model only. `ValidAndSettles` (linear settling and no actuator
  saturation at the 10 degree slew start, together) is reported VIOLATED: z3 finds no (Kp, Kd) meeting both.
  `AxisSettles`, `LinearSettles` and `Unsaturated` are undecided, and z3 gives a witness for each.
  The exit status of `verify` is nonzero when a constraint is violated.
- The "Checks" table in `tool-vcrm.png` is the REDK `Verdicts` query over the design part. Its verdict
  `holds` for `att_final` means the claim is consistent with the model; it is not a satisfaction verdict.
- The SVGs carry a fixed pixel size (700 px or less wide); they scale when placed in an `img` or inline
  SVG at 1000 px.

## Failures and gaps

- None of the five assets failed.
- The `sysml` CLI is not in the opensysml wheel (the wheel starts only the gRPC service), so
  `sysml.views.requirement_view` uses the CLI when `.tools/sysml` (or `$SYSML_CLI`, or PATH) has it, and
  otherwise draws the same view as Mermaid from the API's nodes and edges (`render_view`, which has no
  overlay option) with verdicts from `run_analysis`. That fallback is not the CLI's output.
- The SysML v2 standard library is not fetched: both CLIs embed it, and `sysmlv2 verify --solve` prints the
  same output with and without `--lib`.
- Mermaid output is not rendered to SVG here (no mermaid-cli, no d2, no graphviz `dot`); PlantUML runs from
  its jar with Java.
